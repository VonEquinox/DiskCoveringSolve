# Fresh Cover19 verification evidence

All records here were produced locally on September 5, 2026, separately from
the original archive payloads.

- `independent_replay/`: direct full execution of both original masters in
  extracted review copies, including console logs, stage reports, and an
  additional exact cross-bundle linkage check. The name denotes fresh local
  execution, not a separate external reviewer.
- `repository_replay/`: a second full run of both masters through
  `cover19/run_verification.py`, including fresh exact linkage.
- `environment_and_inputs.json`: Python/compiler/platform information,
  original ZIP sizes and hashes, and standalone proof hashes.
- `release_startup_checks.json`: six fresh real-process failure tests with
  stale reports and assertion-disabled or missing-input startup.
- `release_checks.log`: all Cover11-Cover19 input manifests and the twelve
  Cover19 synthetic runner regression tests. Older chains were not fully
  replayed again for this release.
- `SHA256SUMS`: fixed hashes for the evidence in this directory, excluding
  the checksum file itself.

The supplied alternative `reports/master_failure_tests.json` is not a stage
regenerated by the original master and is intentionally absent from both
fresh replay collections. Its original bytes remain in `alternative_bundle/`.
Optional numerical discovery programs were not executed for acceptance.

Check evidence integrity from the repository root:

```bash
cd cover19/verification
shasum -a 256 -c SHA256SUMS
```

Hashes detect changes; they do not prove mathematical correctness or external
publication time. The fresh master logs and the written arguments must be
reviewed together. To reproduce acceptance, run `make cover19-full` from the
repository root. To retain a new run, use a new `--report-dir` rather than
overwriting this release's fixed records.
